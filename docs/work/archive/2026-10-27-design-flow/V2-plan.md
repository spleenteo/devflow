# V2 — Compose and promote, by hand

**Mandate**: [slices.md § V2](slices.md) (criterion: [frame.md](frame.md); Pen mechanics: [spike](spike-pen-libraries.md), its § Follow-up probe included). **Guidelines**: [development-guidelines.md](../../../development-guidelines.md). **Lessons**: [lessons.md](lessons.md). **Execution rules**: the executor's policy, `agents/executor.md` in the plugin; test level `none`. Never touch `docs/design/flow_home-page.pen`.

## The slice, decided here

- The adapter contract gets named operations: `## Operations` holds `### Session`, `### Open`, `### List`, `### Import`, `### Compose`, `### Promote`, `### Note`, `### Export`, in that order. `/flow:design` cites them as "the adapter's <Name>", so a project's own adapter knows what to fill and the skill stays tool-agnostic.
- Language: the index (its text and rows) and in-file notes are written in the language of the repo's `docs/` documents, whatever the conversation's, worded as `skills/brainstorm/SKILL.md:49`. The template stays English; its text is translated when the folder is not.
- Picking the file: the index's area rows; the skill names the file it picked and why, the user confirms. No area fits: propose a new area file (name agreed), created through the adapter with the library import and a note, plus its index row. A missing index: § First use's offer runs first.
- One logical change per `execute` call: a failing call rolls back whole, `try` included; after a failure, re-read the nodes before anything else, never resend the snippet.
- Library aliases are generated by the tool (e.g. `9`), never chosen: always read from `get_app_state` (`<alias>:<id>`) or `list_libraries()` (`id`), never assumed.
- Promotion asks after the screen is approved, per new component, naming the target library (one library row: that one; several: ask). Preconditions are checked before the first call, so a stop leaves nothing half-done: the area file imports the library; the component's child names are unique (the override remap goes by name); every token it uses exists in the library. Before the second call, `get_app_state` on the area file must list `<alias>:<newId>`; if not (the file is open in the app on a stale copy), ask the user to reopen it, then check again.
- Promotion's second call failing: the library holds the component, the area file its local copy; say so, offer to finish with the second call only after re-reading both files; never re-run the first (it would duplicate the component).
- Import: with the MCP tools, the user adds it in the app (Libraries tab, **+**), then `get_app_state` confirms; with the CLI only, `import_library({ path })` on the user's ok, `path` relative to the shell's working directory (not the edited file; the stored import is relative to the importer), confirmed with `list_libraries()`, falling back to asking in the app. Never the file's JSON by hand.
- Export: only on request, to a folder the user names (asked when not given); each path `Export` returns is checked with `test -f`; a missing one is reported as failed.
- Direction (R7.2): this skill draws and never edits code; building a screen in code, or redrawing what the code does, is proposed in one line with what would change, done only on an ok; by hand with code to write, propose `/flow:dev`.
- Description of `/flow:design` gains what V2 adds: *"Flow's design step, run by Flow's conductors, or by hand with /flow:design. Sets up the project's docs/design/ folder and its index, proposes the medium for a work's design step, composes from the project's design system and promotes approved components into it."*

## Tasks

### T1 — The Pen adapter's operations (critical)
- **What**: in `skills/design-pen/SKILL.md`, replace the `## Operations` stub with the eight subsections, Pen mechanics from the spike and its follow-up:
  - `### Session`: MCP: `filePath` per call, app open. CLI: one `pen interactive -i <file> -o <file>` per file, run from the repo root, commands fed by a heredoc (`pen interactive -i <file> -o <file> <<'EOF'` … `save()`, `exit()`, `EOF`); reading only: `-o` to a scratch copy, never the source; paths given to shell commands are relative to the working directory. One file per call. The one-change-per-call and after-failure rules above (retry through `edits` with `editId`, as the tool asks). Aliases as decided above.
  - `### Open`: `get_app_state`; top-level frames with `Get((n,c)=>{c.skipChildren();Print(n.id,n.name)})`; the file's imports and their aliases (`get_app_state`, or `list_libraries()` in the CLI).
  - `### List`: components from `get_app_state`'s "Reusable components" (`` `<alias>:<id>`: <name> `` for imported ones); tokens from `GetVariables()` (`<alias>:<name>`).
  - `### Import`: as decided above, then the alias read back.
  - `### Compose`: `Insert` frames into the area file; library components as `{type:"ref", ref:"<alias>:<id>"}` with the alias read in Open, overrides with `U(<instance>+"/<child>", {…})`; values as `"$<alias>:<token>"`; a local `reusable: true` component only for a new one the user approved. Never `Replace` or `Delete` an existing node unasked.
  - `### Promote`: the preconditions above; call 1 in the library: `Insert` the component's tree at top level as `reusable: true`, with `$<alias>:x` written `$x` and nested `ref: "<alias>:<id>"` written `ref: "<id>"`, recording the new id and child ids by name; the `get_app_state` check before call 2; call 2 in the area file: each instance of the local component `Replace`d by `{type:"ref", ref:"<alias>:<newId>"}` with its `descendants` override keys remapped old → new child id by child name (`Update` cannot change `ref`), then `Delete` of the local component; the second-call failure rule above.
  - `### Note`: the top-level `note` node: `Update` its content, `Insert` one when missing; it says what the file holds (a library: its components; an area: its screens and imported library), in the language `/flow:design` passes.
  - `### Export`: `Export([<node ids>], "<format>", "<folder>")`, then the `test -f` check above.
  In `## Files`, the Imports bullet: `execute` cannot set `imports`; the app sets it, or the CLI's `import_library` (see `### Import`); the alias is generated. In `## Cautions`, a bullet: before any CLI session on a file, the user saves and closes it in the app, or the app's copy overwrites the change.
- **Files**: `skills/design-pen/SKILL.md`.
- **Verified**: `claude plugin validate .` passes with only the guidelines' expected warnings; `rg -n '^##+ ' skills/design-pen/SKILL.md` prints Requires, Files, Operations, the eight subsections in order, Cautions; `rg -n 'not described yet' skills/design-pen/SKILL.md` prints nothing (exit 1); `rg -c 'import_library' skills/design-pen/SKILL.md` prints 2 or more; `rg -n "<<'EOF'" skills/design-pen/SKILL.md` prints one line or more; `rg -n '\bds:' skills/design-pen/SKILL.md` prints nothing (exit 1).
- **Done**: committed, `Describe the Pen adapter's operations`.
- **Interfaces**: produces the eight subsection names T2 cites.
