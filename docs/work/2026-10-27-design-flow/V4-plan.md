# V4 — `/flow:project`, and the plugin's own docs

**Mandate**: [slices.md § V4](slices.md) (criterion: [frame.md](frame.md); decision: [design runs as a dev phase](../../decisions-log/2026-10-27-design-runs-as-a-dev-phase.md)). **Guidelines**: [development-guidelines.md](../../development-guidelines.md). **Lessons**: [lessons.md](lessons.md). **Execution rules**: the executor's policy, `agents/executor.md` in the plugin; test level `none`. Never touch `docs/design/flow_home-page.pen`.

## The slice, decided here

- **The base.** `/flow:design` writes under `<base>/docs/design/`. By hand, first hit wins: (1) `Home: "<absolute path>"` in the args (quoted: vault paths hold spaces); (2) the working directory, when its `STATUS.md` frontmatter has `project:`; (3) the repo root, `git rev-parse --show-toplevel`. Called mode (`Shaping:`) skips (1) and (2) and uses `git rev-parse --show-toplevel`: `/flow:dev` runs in a repo, and its args are unchanged. A folder from (1) or (2) is a project home only when `grep -m1 '^project:' <dir>/STATUS.md` finds the line; a named folder without it: say so and stop. From there, walk up while `parent:` isn't `null` (a sub-project sits inside its parent's folder, so up is the folder above, checked again) and use that top home as the base: one design system per project. None found: ask for a project home or a repo; still none: say it works in a repo or a project home, and stop.
- **`design:` and `presets:` in a project** live only in the top home's `STATUS.md` frontmatter (`parent: null`); sub-projects don't carry them. In a repo both stay in `.flow.yml`. The adapter chain: (1) `presets:` (in `.flow.yml` in a repo; in the top home's `STATUS.md` in a project home), the pair `design=<skill>`; (2) `stack_presets`; (3) the shipped list. The first artifacts-only case reads "no `design:` where the base keeps it".
- **Commits.** `/flow:design` never commits, in either place. In a project home its files are committed with the slice's close when the home is under version control (the work reference § Commits, project); in a plain folder the files are the record. First use already moves with `mv` when a file isn't tracked.
- **The pen adapter** runs its CLI from the base and builds export folders from it: "repo root" becomes "the base `/flow:design` names (repo root or project home)".
- **`/flow:project`, `step: plan`.** An action is written *"/flow:design: <artifact>"* only when the slice's section of `slices.md` or the action's Done calls for something people will look at (a deck, a page, a poster, a flyer, a flow to click through); never for actions done in the world (calls, meetings, payments, permits). Who: the user; Done when: the user approves the artifact. While writing the plan, the proposal reads `design:` from the top home's `STATUS.md` (walking up `parent:` as above) and names the medium by `/flow:design`'s § Medium rule (a Claude artifact for an interactive or exploratory need, or when the top home has no `design:`; a design file through the tool for a static artifact with `design:` set), with the reason naming which case held, and the line to type, carrying the top home's path: `/flow:design Home: "<absolute top home path>" <the artifact, in a few words>`. No `Shaping:` line: the user runs it by hand, in this session or another.
- **`step: execute`.** A `/flow:design` row closes when the user reports the artifact approved; its files ride the slice's close commit when the home is under version control.
- **The project template** gains `design: <tool, only when set: pen>` and `presets: <[design=<skill>], only when set>` after `appetite:`; the **Both** paragraph says they name the tool `/flow:design` uses and its adapter, live only in the top home (`parent: null`, sub-projects don't carry them), are present only when set (on the user's word, never guessed), and without `design:` only Claude artifacts are offered.

## Deviations from the mandate

- `skills/design-pen/SKILL.md` changes too (T1): its CLI runs "from the repo root", which a project home doesn't have, and its mapping line names only `.flow.yml`.
- The grid's column count lives in `site/styles.css`, not `site/index.html`: T7 edits both.
- The site has no Breadboard item (Shape covers shaping and breadboarding), so "if it shows breadboard" doesn't hold literally; the reading chosen: a separate Design item (05), Slice becomes 06, six columns.
- The README gains a `/flow:design` row in Usage and a paragraph on `/flow:project`'s `/flow:design` rows, and `docs/architecture.md` a sentence in its `/flow:project` paragraph: docs that list the skills and describe `/flow:project` would be wrong without them.
- A sub-project uses its top home's `docs/design/`, `design:` and `presets:`: one design system per project, as R8.1 reads it.
- `presets:` joins `design:` in the top home's `STATUS.md`, so a project home can replace the shipped adapter (R4.2) without a `.flow.yml`.
